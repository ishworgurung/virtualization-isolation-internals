Throughput: our SPSC ring vs std::sync::mpsc vs Mutex<VecDeque>.

One producer thread sends 0..N; one consumer thread receives and checks the sum (0 + 1 + … + N-1 = N(N-1)/2), which proves nothing was lost or duplicated.

How each one waits when the queue is full/empty:

  • SPSC ring and Mutex<VecDeque>: spin (busy-wait with a CPU pause hint).
  • std::sync::mpsc::sync_channel: a real blocking channel — it spins briefly, then parks the thread and is woken by the other side. That wake-up machinery is part of what its number includes. (Since Rust 1.67 std’s channel is based on crossbeam-channel, whose bounded flavour is a lock-free array queue — which is why it comes so close to the ring.)

Run: cargo run –release –bin spsc_bench Caveat: numbers depend heavily on core placement (same core pair? SMT siblings? same CCX?). Treat ratios as indicative, not absolute.
