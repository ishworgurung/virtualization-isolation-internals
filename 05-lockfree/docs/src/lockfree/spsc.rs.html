1//! A bounded, wait-free single-producer / single-consumer ring buffer.
2//!
3//! This is the data structure behind virtio virtqueues, io_uring's SQ/CQ and
4//! most audio/network fast paths.
5//!
6//! ## What problem it solves
7//!
8//! One thread (the **producer**) creates items; another (the **consumer**)
9//! processes them, in the same order (**FIFO**: first in, first out). They run
10//! at different speeds, so we need a waiting room between them: a **queue**.
11//! "Bounded" means the queue has a fixed maximum size; when it is full, `push`
12//! fails instead of allocating more memory. "Single-producer/single-consumer"
13//! (SPSC) means exactly one thread pushes and exactly one thread pops.
14//!
15//! ## Refresher: the ring buffer (circular buffer)
16//!
17//! A queue stored in a fixed array. Two positions: **head** (where the next
18//! item will be read) and **tail** (where the next item will be written).
19//! Push writes at tail and moves tail forward; pop reads at head and moves
20//! head forward. When a position reaches the end of the array, it wraps to
21//! slot 0 — the array is used as if it were a circle:
22//!
23//! ```text
24//!   capacity 8, after pushing 1..=6 and popping 1..=2:
25//!
26//!   slot:   0   1   2   3   4   5   6   7
27//!         [ .   .   3   4   5   6   .   . ]
28//!                   ^               ^
29//!                  head=2          tail=6          fill = 6 - 2 = 4
30//!
31//!   push 7, 8, 9: tail passes the end and wraps to slot 0
32//!
33//!   slot:   0   1   2   3   4   5   6   7
34//!         [ 9   .   3   4   5   6   7   8 ]
35//!               ^   ^
36//!          tail=9  head=2      (tail as a counter is 9; its slot is 9 % 8 = 1)
37//! ```
38//!
39//! Nothing is ever shifted or copied around; only the two positions move.
40//! Both push and pop are O(1).
41//!
42//! ## Why this needs no lock and no CAS
43//!
44//! Each index has exactly **one writer**:
45//!
46//! ```text
47//!   slots:   [ . . X X X X . . ]
48//!                  ^       ^
49//!                head      tail
50//!         consumer writes   producer writes
51//!         (pop advances)    (push advances)
52//! ```
53//!
54//! * `tail` — next slot the producer will fill. Only the producer stores it.
55//! * `head` — next slot the consumer will read. Only the consumer stores it.
56//!
57//! Each side only *reads* the other side's index, to learn how far it may go.
58//! Two threads never race to write the same variable, so plain atomic loads
59//! and stores are enough; no compare-and-swap is needed.
60//!
61//! ## Free-running counters, masks and wrap-around
62//!
63//! `head` and `tail` are **free-running** `usize` counters: they count every
64//! item ever pushed/popped and are never reduced mod capacity. The actual slot
65//! is `counter & mask`, where `mask = capacity - 1` (capacity is a power of two;
66//! see the bits refresher in `lib.rs`):
67//!
68//! ```text
69//!   capacity 8 -> mask 7 = 0b0111
70//!   counter 13 = 0b1101;  13 & 0b0111 = 0b0101 = 5   (same as 13 % 8)
71//! ```
72//!
73//! * fill level = `tail.wrapping_sub(head)`
74//! * empty ⇔ `tail == head`
75//! * full  ⇔ `tail - head == capacity`
76//!
77//! This removes the classic "keep one slot empty to tell full from empty"
78//! trick: if you stored slot numbers (0..cap) instead of counters, an empty
79//! ring and a full ring would both have `head == tail`.
80//!
81//! **Why `wrapping_sub` is still right after the counter overflows.** A
82//! `usize` counter wraps back to 0 after 2^64 increments (at a billion pushes a
83//! second, that takes ~584 years, but correctness should not depend on that).
84//! The same thing, shrunk to a `u8` so the numbers are readable (u8 wraps at
85//! 256):
86//!
87//! ```text
88//!   head = 254, then 3 pushes: tail = 254 + 3 = 257 -> wraps to 1
89//!   tail - head = 1 - 254 = -253 -> as u8 (mod 256): 256 - 253 = 3   correct!
90//! ```
91//!
92//! Subtraction mod 2^N gives the right distance as long as the true distance is
93//! below 2^N, which it always is (it is at most the capacity).
94//!
95//! ## Memory ordering — the whole game
96//!
97//! Modern CPUs and compilers reorder memory accesses whenever a *single* thread
98//! cannot tell the difference. Another thread can. Orderings tell both what
99//! must not be reordered:
100//!
101//! Push:  write the slot, then `tail.store(.., Release)`.
102//! Pop:   `tail.load(Acquire)`, then read the slot.
103//!
104//! Analogy: the producer puts a parcel in a locker (writes the slot), then
105//! raises a flag (stores tail). The consumer waits for the flag, then opens the
106//! locker. Without ordering, the flag could be raised before the parcel is in
107//! the locker, and the consumer would find it empty.
108//!
109//! The Release store "publishes" every write that came before it in program
110//! order (the slot contents). The Acquire load that observes the new `tail`
111//! *synchronises-with* it, guaranteeing the slot contents are visible. With
112//! `Relaxed` on both sides the consumer could see the new `tail` but stale slot
113//! bytes — on ARM/POWER for real, on x86 only via compiler reordering.
114//!
115//! The symmetric edge protects the *reuse* of a slot: the consumer finishes
116//! reading, then `head.store(.., Release)`; the producer's `head.load(Acquire)`
117//! guarantees it will not overwrite a slot still being read.
118//!
119//! ```text
120//!   producer                              consumer
121//!   --------                              --------
122//!   buf[t & mask] = value
123//!   tail.store(t+1, Release)  ─────────▶  tail.load(Acquire) sees t+1
124//!                                         value = buf[h & mask]
125//!   head.load(Acquire) sees h+1  ◀──────  head.store(h+1, Release)
126//!   (now slot h may be overwritten)
127//! ```
128//!
129//! On x86-64 an Acquire load and a Release store compile to ordinary `mov`
130//! instructions (the hardware already provides that ordering); they only stop
131//! the *compiler* from reordering. On ARM64 they become `ldar`/`stlr`.
132//!
133//! ## Two performance details
134//!
135//! 1. **Cache-line padding** of `head` and `tail` (see [`crate::padded`]): they
136//!    are written by different cores, so sharing a line would false-share.
137//! 2. **Cached remote index.** Loading the other side's index pulls its cache
138//!    line across cores. Each side keeps a private copy and only re-reads the
139//!    real one when the ring *looks* full/empty. Under steady load this cuts
140//!    cross-core traffic to about one line transfer per *batch* instead of per item.
141//!
142//! ## Rust types used here, briefly
143//!
144//! * `Arc<T>` — a reference-counted pointer that can be shared between
145//!   threads. `Producer` and `Consumer` each hold one; the `Shared` state is
146//!   freed when the *last* of them is dropped.
147//! * `Box<[T]>` — a fixed-size heap array (like `Vec<T>` without the ability to
148//!   grow).
149//! * `UnsafeCell<T>` — the only legal way in Rust to mutate something through a
150//!   shared reference `&`. Normally `&` means "read-only"; `UnsafeCell` opts out
151//!   and makes *you* responsible for preventing data races.
152//! * `MaybeUninit<T>` — room for a `T` that may or may not currently hold a
153//!   value. Rust never reads or drops it on its own; we track which slots are
154//!   full (the ones in `[head, tail)`).
155//! * `unsafe { .. }` — "compiler, I have checked the rules you can't check".
156//!   Every `unsafe` block below has a `SAFETY:` comment saying why it holds.
157//! * `Result<(), T>` / `Option<T>` — Rust's way to return "success or failure"
158//!   and "a value or nothing" without exceptions or null.
159
160use crate::padded::CachePadded;
161use std::cell::UnsafeCell;
162use std::mem::MaybeUninit;
163// `Ordering::*` imports `Relaxed`, `Acquire`, `Release`, ... by their short names.
164use std::sync::atomic::{AtomicUsize, Ordering::*};
165use std::sync::Arc;
166
167/// State shared by the two ends.
168struct Shared<T> {
169    /// Slot storage. `UnsafeCell` because producer and consumer both touch the
170    /// buffer through `&Shared`; `MaybeUninit` because most slots hold no value.
171    /// (`UnsafeCell` is Rust's only legal way to mutate through a shared `&`;
172    /// `MaybeUninit<T>` is storage for a `T` that may not be initialised, and
173    /// that Rust therefore never drops or reads on its own.)
174    buf: Box<[UnsafeCell<MaybeUninit<T>>]>,
175    /// `capacity - 1`; capacity is a power of two so `i & mask == i % capacity`.
176    /// Example: capacity 1024 -> mask 1023 = 0b11_1111_1111 (ten 1-bits), so
177    /// `i & mask` keeps the low 10 bits of `i`: a slot number in 0..=1023.
178    mask: usize,
179    /// Written only by the consumer.
180    head: CachePadded<AtomicUsize>,
181    /// Written only by the producer.
182    tail: CachePadded<AtomicUsize>,
183}
184
185// SAFETY: the protocol guarantees a slot is accessed by at most one side at a
186// time (producer owns slots in [tail, head+cap), consumer owns [head, tail)),
187// with acquire/release edges between hand-overs. `T: Send` because values move
188// across threads.
189// (Without these impls the compiler would refuse to share `Shared` between
190// threads, because it contains `UnsafeCell`, which is not `Sync`.
191// `Send` = "may be moved to another thread"; `Sync` = "may be accessed through
192// `&` from several threads at once".)
193unsafe impl<T: Send> Sync for Shared<T> {}
194unsafe impl<T: Send> Send for Shared<T> {}
195
196impl<T> Drop for Shared<T> {
197    /// Drop any items still in the queue (both ends are gone, so we have `&mut`).
198    /// Runs when the last `Arc` — i.e. the later of Producer/Consumer — is dropped.
199    /// `get_mut` reads the atomics without any synchronisation, which is sound
200    /// because `&mut self` proves no other thread can access them any more.
201    /// (Without this, items still queued would leak: `MaybeUninit` never drops
202    /// its contents by itself.)
203    fn drop(&mut self) {
204        let head = *self.head.get_mut();
205        let tail = *self.tail.get_mut();
206        let mut i = head;
207        // Walk the occupied counters head, head+1, ..., tail-1. `!=` rather than
208        // `<` because the counters may have wrapped (tail can be numerically
209        // smaller than head).
210        while i != tail {
211            // SAFETY: slots in [head, tail) are initialised and unread.
212            unsafe { (*self.buf[i & self.mask].get()).assume_init_drop() };
213            i = i.wrapping_add(1);
214        }
215    }
216}

218/// The sending half. Not `Clone` — exactly one producer is the invariant that
219/// makes this lock-free without CAS. `push` takes `&mut self`, so the type
220/// system also prevents two threads from pushing through the same handle.
221pub struct Producer<T> {
222    shared: Arc<Shared<T>>,
223    /// Our private, always-current tail (we are its only writer).
224    tail: usize,
225    /// Stale copy of the consumer's head; refreshed only when the ring looks full.
226    cached_head: usize,
227}
228
229/// The receiving half. Also not `Clone`.
230pub struct Consumer<T> {
231    shared: Arc<Shared<T>>,
232    /// Our private, always-current head (we are its only writer).
233    head: usize,
234    /// Stale copy of the producer's tail; refreshed only when the ring looks empty.
235    cached_tail: usize,
236}

238/// Create a ring holding at least `capacity` items (rounded up to a power of two
239/// so that `& mask` replaces `%`; minimum 2).
240///
241/// `next_power_of_two`: 2 -> 2, 3 -> 4, 5 -> 8, 1000 -> 1024.
242pub fn channel<T>(capacity: usize) -> (Producer<T>, Consumer<T>) {
243    let cap = capacity.max(2).next_power_of_two();
244    // Build `cap` empty slots. `(0..cap).map(..)` produces one value per number;
245    // `.collect()` gathers them into the `Box<[_]>` asked for by the type.
246    let buf: Box<[_]> = (0..cap).map(|_| UnsafeCell::new(MaybeUninit::uninit())).collect();
247    let shared = Arc::new(Shared {
248        buf,
249        mask: cap - 1,
250        head: CachePadded(AtomicUsize::new(0)),
251        tail: CachePadded(AtomicUsize::new(0)),
252    });
253    (
254        // `shared.clone()` copies the Arc *pointer* (refcount 1 -> 2), not the ring.
255        Producer { shared: shared.clone(), tail: 0, cached_head: 0 },
256        Consumer { shared, head: 0, cached_tail: 0 },
257    )
258}
259
260impl<T> Producer<T> {
261    /// Try to enqueue. Returns the value back if the ring is full. Never blocks.
262    /// (Giving the value back in `Err(value)` lets the caller retry without
263    /// losing it; the ring never holds a value it did not accept.)
264    pub fn push(&mut self, value: T) -> Result<(), T> {
265        let cap = self.shared.mask + 1;
266
267        // Fast path uses the stale head: it can only UNDER-estimate free space
268        // (the consumer only ever advances), so "not full" here is always true.
269        //
270        // Example, cap = 8: we last saw head = 10, so cached_head = 10; tail = 18.
271        // 18 - 10 = 8 == cap: looks full. Meanwhile the consumer has popped up
272        // to head = 13. Reloading gives 18 - 13 = 5 < 8: room for 3 more, and
273        // we won't need to look at the consumer's cache line again for 3 pushes.
274        if self.tail.wrapping_sub(self.cached_head) == cap {
275            // Looks full: pay for one real load. Acquire pairs with the
276            // consumer's Release store of `head`, so the consumer's read of the
277            // slot happens-before we overwrite it.
278            self.cached_head = self.shared.head.load(Acquire);
279            if self.tail.wrapping_sub(self.cached_head) == cap {
280                return Err(value); // genuinely full
281            }
282        }
283
284        // SAFETY: the slot at `tail` is outside [head, tail), so the consumer
285        // is not touching it, and we are the only producer.
286        // `write` stores without dropping the old (uninitialised) contents.
287        // `.get()` turns `&UnsafeCell<X>` into a raw `*mut X`; `(*ptr)` then
288        // dereferences it (the unsafe part).
289        unsafe { (*self.shared.buf[self.tail & self.shared.mask].get()).write(value) };
290
291        self.tail = self.tail.wrapping_add(1);
292        // RELEASE: publish the slot write above together with the new tail.
293        self.shared.tail.store(self.tail, Release);
294        Ok(())
295    }
296}
297
298impl<T> Consumer<T> {
299    /// Try to dequeue. Returns `None` if the ring is empty. Never blocks.
300    pub fn pop(&mut self) -> Option<T> {
301        // Mirror image of `push`: the stale tail can only UNDER-estimate how many
302        // items are ready, so "not empty" according to the cache is always true.
303        if self.head == self.cached_tail {
304            // Looks empty: refresh. Acquire pairs with the producer's Release
305            // store of `tail` => slot contents are visible after this load.
306            self.cached_tail = self.shared.tail.load(Acquire);
307            if self.head == self.cached_tail {
308                return None;
309            }
310        }
311
312        // SAFETY: slot at `head` is inside [head, tail): initialised by the
313        // producer, and we are the only consumer. `assume_init_read` moves the
314        // value out, leaving the slot logically uninitialised again.
315        let value = unsafe { (*self.shared.buf[self.head & self.shared.mask].get()).assume_init_read() };
316
317        self.head = self.head.wrapping_add(1);
318        // RELEASE: tell the producer this slot may be reused (our read of it
319        // above must not be reordered after this store).
320        self.shared.head.store(self.head, Release);
321        Some(value)
322    }
323}

326mod tests {

330    /// Single-threaded basics: empty, fill to capacity, full, FIFO drain.
331    #[test]
332    fn fifo_and_full_empty() {
333        let (mut p, mut c) = channel::<u32>(4);
334        assert_eq!(c.pop(), None);
335        for i in 0..4 {
336            p.push(i).unwrap();
337        }
338        assert_eq!(p.push(99), Err(99)); // full
339        for i in 0..4 {
340            assert_eq!(c.pop(), Some(i));
341        }
342        assert_eq!(c.pop(), None);
343    }
344
345    /// Capacity 2, 1000 items: the slot index wraps around ~500 times.
346    #[test]
347    fn wraps_around_many_times() {
348        let (mut p, mut c) = channel::<usize>(2);
349        for i in 0..1000 {
350            p.push(i).unwrap();
351            assert_eq!(c.pop(), Some(i));
352        }
353    }
354
355    /// Real concurrency: a producer thread and this (consumer) thread. Any
356    /// ordering bug would show up as a lost, duplicated or out-of-order value.
357    #[test]
358    fn two_threads_preserve_order_and_sum() {
359        const N: usize = 200_000;
360        let (mut p, mut c) = channel::<usize>(64);
361        // `move` hands the producer end to the new thread (ownership moves).
362        let t = std::thread::spawn(move || {
363            for i in 0..N {
364                while p.push(i).is_err() {
365                    std::hint::spin_loop(); // CPU hint: "busy-waiting" (x86 `pause`)
366                }
367            }
368        });
369        let mut expect = 0;
370        while expect < N {
371            if let Some(v) = c.pop() {
372                assert_eq!(v, expect); // strict FIFO
373                expect += 1;
374            }
375        }
376        t.join().unwrap();
377    }
378
379    /// Items still queued when both ends are dropped must be dropped exactly once.
380    #[test]
381    fn leftover_items_are_dropped() {
382        static DROPS: AtomicUsize = AtomicUsize::new(0);
383        struct D;
384        impl Drop for D {
385            fn drop(&mut self) {
386                DROPS.fetch_add(1, Relaxed);
387            }
388        }
389        let (mut p, c) = channel::<D>(8);
390        for _ in 0..5 {
391            assert!(p.push(D).is_ok());
392        }
393        drop((p, c));
394        assert_eq!(DROPS.load(Relaxed), 5);
395    }
